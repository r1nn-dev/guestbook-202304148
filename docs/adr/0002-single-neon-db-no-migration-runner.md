# 로컬과 배포가 Neon DB 하나를 같이 쓰고, 마이그레이션 러너는 두지 않는다

로컬 개발과 Vercel 배포는 같은 `DATABASE_URL`, 즉 같은 Neon Postgres DB를 쓴다. 스키마는 Neon 콘솔에서 직접 실행했고, `db/schema.sql`은 그 내용을 기록으로만 남긴다. 테이블이 하나이고 시험 시간이 짧아서, 환경을 나누고 마이그레이션 도구를 들이는 비용이 얻는 이점보다 크다고 판단했다.

## Consequences

- 로컬에서 남긴 글이나 지운 글은 배포된 방명록에 곧바로 반영된다. 로컬에서 테스트용 데이터를 넣을 때 주의해야 한다.
- 스키마를 바꾸려면 Neon에서 SQL을 직접 실행하고 `db/schema.sql`도 같이 고쳐야 한다. 둘이 어긋나도 알려주는 장치는 없다.
- 자동 테스트는 DB에 닿지 않는 순수 로직만 다룬다.
