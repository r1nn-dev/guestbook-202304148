# 01: 강제 삭제와 사용성 개선 묶음

**What to build:** 방명록에 일곱 가지를 한 번에 더한다. 스펙은 `.scratch/guestbook-extras/spec.md`이고, 관리자 관련은 ADR 0003을 따른다.

1. **강제 삭제:** 관리자는 기존 삭제 폼에 관리자 비밀번호를 입력해 어떤 글이든 지운다. 삭제 폼에는 "관리자 비밀번호도 사용할 수 있습니다." 안내가 보인다.
2. **오류 화면:** 방명록을 불러오지 못하면 한국어 안내와 "다시 시도" 버튼이 보인다. 헤더와 푸터는 남는다.
3. **로딩 표시:** 방명록을 불러오는 동안 글 카드 스켈레톤이 보인다.
4. **총 글 수:** 헤더에 "총 N개"가 보이고, 목록 위의 "전체 글 N개"는 사라진다.
5. **메시지 글자 수:** 작성·수정 메시지 입력칸 아래에 "현재/500"이 보인다. 500자를 넘으면 숫자가 빨간색이 되고 버튼이 막힌다.
6. **Ctrl+Enter 등록:** 메시지 입력칸에서 Ctrl/Cmd+Enter로 제출한다.
7. **비밀번호 보기 토글:** 모든 비밀번호 입력칸 옆의 눈 아이콘으로 값을 보거나 숨긴다.

DB 스키마와 기존 API 계약은 바꾸지 않는다. 달라지는 것은 `DELETE`의 강제 삭제 분기 하나뿐이다.

**Blocked by:** None (can start immediately). 앞선 `.scratch/mini-guestbook` 티켓 01~04는 모두 완료됐다.

**Status:** ready-for-agent

### 순수 로직과 테스트 (TDD, 기존 seam)

- [ ] 입력 검증 모듈이 글자 수 세기 함수를 내보낸다.
  - 코드포인트 기준으로 세고, trim할지는 인자로 받는다.
  - 기존 메시지·이름·비밀번호 검증도 이 함수로 센다.
- [ ] 글자 수 테스트:
  - 이모지를 1글자로 세는지
  - trim 옵션에 따라 앞뒤 공백을 빼는지
  - 한글과 줄바꿈이 섞인 문자열
  - 500자 경계에서 기존 메시지 검증과 같은 판정인지
- [ ] 글 비밀번호 모듈에 관리자 비밀번호 비교 함수를 추가한다.
  - 형태는 `(입력, 설정값 | undefined) → boolean`이다. 환경 변수를 직접 읽지 않는다.
  - SHA-256으로 같은 길이로 만든 뒤 `timingSafeEqual`로 비교한다.
  - 설정값이 없거나 빈 문자열이면 항상 false다.
- [ ] 관리자 비밀번호 테스트:
  - 맞으면 true, 틀리면 false
  - 길이가 달라도 예외 없이 false
  - 설정값이 undefined이거나 빈 문자열이면, 빈 입력을 포함한 어떤 입력이든 false
  - 앞뒤 공백 한 글자만 달라도 false
- [ ] 기존 테스트 49개가 그대로 통과한다. 상수 값만 확인하는 테스트는 추가하지 않는다.

### 강제 삭제

- [ ] `DELETE /api/entries/[id]` 판정 순서:
  - 400: 글 번호 → 요청 본문(4~50자 검증은 관리자 비밀번호에도 적용)
  - 관리자 비밀번호가 맞으면 삭제한다. 삭제된 행이 없으면 404, 있으면 204.
  - 틀리면 기존 흐름: 404 → 403 → 204
- [ ] 라우트가 `ADMIN_PASSWORD`를 읽어 비교 함수에 넘긴다. 강제 삭제의 응답은 일반 삭제와 구분되지 않는다.
- [ ] `PATCH`는 바꾸지 않는다. 관리자 비밀번호로 수정하면 403이다.
- [ ] 삭제 폼에만 "관리자 비밀번호도 사용할 수 있습니다."를 작은 글씨로 표시한다.

### 오류 화면과 로딩 표시

- [ ] 루트 세그먼트에 오류 화면(클라이언트 컴포넌트)을 둔다.
  - 한국어 안내와 "다시 시도" 버튼을 보여주고, 버튼은 `retry()`를 호출한다(Next 16 문서 확인).
  - 오류 메시지나 스택은 화면에 보여주지 않는다.
  - `global-error`는 만들지 않는다.
- [ ] 루트 세그먼트에 로딩 화면을 둔다. 글 카드 모양 스켈레톤 3개를 `animate-pulse`로 보여준다.

### 총 글 수

- [ ] 글 저장소에 총 글 수 조회를 추가한다.
- [ ] 헤더에 "총 N개"를 표시하는 비동기 서버 컴포넌트를 둔다.
  - 스스로 오류를 잡아, 실패하면 개수만 숨긴다.
  - Suspense로 감싸서, 불러오는 동안 레이아웃을 막지 않는다.
- [ ] 레이아웃이 요청마다 DB를 읽도록 하는 데 추가 설정이 필요한지 이 버전의 Next 문서로 확인하고 반영한다.
- [ ] 방명록 페이지의 "전체 글 N개" 제목을 없앤다. 빈 방명록 안내는 유지한다.
- [ ] 글을 남기거나 지우면 `router.refresh()`로 헤더 개수도 함께 바뀐다.

### 메시지 글자 수와 Ctrl+Enter

- [ ] 작성·수정 메시지 입력칸 아래에 "현재/500"을 표시한다.
  - 숫자는 trim한 값을 코드포인트로 센 결과다.
  - 500은 검증 모듈의 상수에서 가져온다.
- [ ] 500자를 넘으면 숫자를 빨간색으로 바꾸고 등록·저장 버튼을 비활성화한다.
- [ ] 메시지 입력칸의 `maxLength`를 없앤다. 이름·비밀번호칸의 `maxLength`는 유지한다.
- [ ] 메시지 입력칸에서 Ctrl+Enter 또는 Cmd+Enter를 누르면 `requestSubmit()`으로 제출한다.
  - 한글 조합 중(`isComposing`)이면 무시한다.
  - 처리 중이거나 500자를 넘었으면 제출하지 않는다.
  - Enter만 누르면 줄바꿈한다.
  - 작성·수정 두 입력칸이 같은 코드를 쓴다.

### 비밀번호 보기 토글

- [ ] 공용 비밀번호 입력 컴포넌트를 만든다.
  - 인라인 SVG 눈 아이콘 버튼을 둔다(`type="button"`, 아이콘 라이브러리 없음).
  - `aria-label`은 상태에 따라 "비밀번호 보기"/"비밀번호 숨기기"다.
  - 기존 입력 속성(`minLength`, `maxLength`, `required`, `autoComplete`)을 그대로 넘긴다.
- [ ] 작성·수정·삭제의 비밀번호칸을 모두 이 컴포넌트로 바꾼다. 패널을 닫았다 열면 다시 가려진 상태다.
