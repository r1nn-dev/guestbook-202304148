# 미니 방명록 추가 기능

## Problem Statement

미니 방명록의 기본 기능(글 남기기, 보기, 수정, 삭제)은 동작하지만, 쓰다 보면 불편하거나 곤란한 점이 있다.

- 부적절한 글이 올라와도, 글 비밀번호를 모르면 누구도 그 글을 지울 수 없다.
- DB에 문제가 생기면 Next 기본 오류 화면이 떠서 앱이 망가진 것처럼 보인다. 첫 연결이 느릴 때는 빈 화면이 잠깐 보인다.
- 메시지를 쓰는 동안 500자 제한까지 얼마나 남았는지 알 수 없다. 입력칸의 제한은 이모지가 섞이면 서버 규칙과 다르게 동작한다.
- 방명록의 총 글 수가 목록 위에 있어서, 화면 상단에서는 바로 보이지 않는다.
- 키보드만으로 글을 등록할 수 없고, 글 비밀번호를 제대로 입력했는지 눈으로 확인할 수 없다.

## Solution

일곱 가지를 추가한다. 기존 결정(`CONTEXT.md`, ADR 0001~0002)은 그대로 두고, 관리자 관련은 ADR 0003을 따른다.

1. **강제 삭제:** 관리자는 기존 삭제 폼에 글 비밀번호 대신 관리자 비밀번호를 입력해 어떤 글이든 지울 수 있다. 삭제 폼에는 "관리자 비밀번호도 사용할 수 있습니다."라는 안내가 보인다.
2. **오류 화면:** 방명록을 불러오지 못하면 한국어 안내와 "다시 시도" 버튼이 보인다. 헤더와 개발자 정보는 그대로 남는다.
3. **로딩 표시:** 방명록을 불러오는 동안 글 카드 모양의 스켈레톤이 보인다.
4. **총 글 수:** 헤더에 "총 N개"가 보인다. 목록 위의 "전체 글 N개"는 없앤다.
5. **메시지 글자 수:** 작성·수정 입력칸 아래에 "123/500"이 보인다. 500자를 넘으면 숫자가 빨간색이 되고 등록·저장 버튼이 막힌다.
6. **Ctrl+Enter 등록:** 메시지 입력칸에서 Ctrl+Enter(Mac은 Cmd+Enter)로 제출한다.
7. **비밀번호 보기 토글:** 모든 비밀번호 입력칸 옆의 눈 아이콘으로 입력한 값을 보거나 숨긴다.

용어는 `CONTEXT.md`를 따른다. 특히 **관리자**, **관리자 비밀번호**, **강제 삭제**, **총 글 수**를 쓴다.

## User Stories

### 강제 삭제

1. 관리자로서, 글 비밀번호를 몰라도 관리자 비밀번호로 어떤 글이든 지우고 싶다. 그래야 부적절한 글을 치울 수 있다.
2. 관리자로서, 따로 로그인하거나 다른 화면으로 가지 않고, 글 안의 기존 삭제 폼에서 강제 삭제하고 싶다.
3. 관리자로서, 삭제 폼에서 "관리자 비밀번호도 사용할 수 있습니다." 안내를 보고 싶다. 그래야 어디에 입력하는지 알 수 있다.
4. 관리자로서, 강제 삭제한 글이 방명록에서 바로 사라지기를 원한다.
5. 관리자로서, 이미 지워진 글을 강제 삭제하려 하면 "글을 찾을 수 없습니다."를 보고 싶다.
6. 관리자로서, 관리자 비밀번호를 잘못 입력했을 때 그 값이 우연히 글 비밀번호와 같지 않다면, 일반 삭제처럼 "비밀번호가 일치하지 않습니다."를 보고 싶다.
7. 방문자로서, 관리자 비밀번호로는 글을 지울 수만 있고 수정은 못 하기를 원한다. 그래야 내 글의 메시지는 나만 바꿀 수 있다.
8. 글쓴이로서, 강제 삭제 기능이 생겨도 내 글 비밀번호로 수정·삭제하는 방식은 그대로이기를 원한다.
9. 방문자로서, 삭제 응답만 보고 관리자가 지웠는지 글쓴이가 지웠는지 알 수 없기를 원한다(둘 다 204).
10. 운영자로서, 관리자 비밀번호가 설정돼 있지 않으면 강제 삭제가 아예 꺼지기를 원한다. 그래야 설정을 빠뜨려도 빈 값으로 뚫리지 않는다.
11. 운영자로서, 관리자 비밀번호 비교에 걸리는 시간이나 길이 차이로 정답을 추측할 수 없기를 원한다.
12. 운영자로서, 관리자 비밀번호가 코드나 저장소에 들어가지 않고 환경 변수로만 관리되기를 원한다.

### 오류 화면과 로딩 표시

13. 방문자로서, 방명록을 불러오지 못하면 "일시적인 문제로 방명록을 불러오지 못했습니다. 잠시 후 다시 시도해주세요." 같은 한국어 안내를 보고 싶다.
14. 방문자로서, 오류 화면의 "다시 시도" 버튼을 눌러 새로고침 없이 방명록을 다시 불러오고 싶다.
15. 채점자로서, 오류가 나도 헤더와 푸터의 개발자 정보는 계속 보이기를 원한다.
16. 방문자로서, 방명록을 불러오는 동안 빈 화면 대신 글 카드 모양의 스켈레톤을 보고 싶다.

### 총 글 수

17. 방문자로서, 헤더에서 방명록의 총 글 수("총 N개")를 바로 보고 싶다.
18. 방문자로서, 글을 남기거나 지우면 헤더의 총 글 수도 바로 바뀌기를 원한다.
19. 방문자로서, 같은 숫자가 화면에 두 번 보이지 않기를 원한다. 그래서 목록 위의 "전체 글 N개"는 없앤다.
20. 방문자로서, 총 글 수만 불러오지 못했을 때는 개수만 사라지고 헤더의 나머지는 그대로 보이기를 원한다.
21. 방문자로서, 글이 하나도 없으면 "총 0개"와 첫 글을 남겨보라는 안내를 함께 보고 싶다.

### 메시지 글자 수

22. 방문자로서, 메시지를 쓰는 동안 입력칸 아래에서 "현재 글자 수/500"을 보고 싶다. 그래야 얼마나 더 쓸 수 있는지 안다.
23. 글쓴이로서, 메시지를 수정할 때도 같은 글자 수 표시를 보고 싶다.
24. 방문자로서, 이모지 하나가 1글자로 세어지기를 원한다. 그래야 서버 판정과 화면 숫자가 같다.
25. 방문자로서, 앞뒤 공백은 저장되지 않으니 글자 수에도 들어가지 않기를 원한다.
26. 방문자로서, 500자를 넘으면 숫자가 빨간색이 되고 등록·저장 버튼이 막히기를 원한다. 그래야 서버에서 거부당하기 전에 알 수 있다.
27. 방문자로서, 이모지를 많이 써도 500자 전에 입력이 막히지 않기를 원한다.

### Ctrl+Enter 등록

28. 방문자로서, 메시지 입력칸에서 Ctrl+Enter로 글을 등록하고 싶다. 그래야 마우스로 버튼을 누르지 않아도 된다.
29. Mac을 쓰는 방문자로서, Cmd+Enter로도 등록하고 싶다.
30. 글쓴이로서, 수정 입력칸에서도 Ctrl+Enter로 저장하고 싶다.
31. 한글을 입력하는 방문자로서, 글자를 조합하는 중에 Ctrl+Enter를 눌러도 마지막 글자가 두 번 들어가거나 조합 중인 글자로 제출되지 않기를 원한다.
32. 방문자로서, Ctrl+Enter로 제출해도 버튼으로 제출할 때와 똑같이 입력 검증과 오류 안내가 동작하기를 원한다.
33. 방문자로서, 요청을 처리하는 중이거나 500자를 넘었을 때는 Ctrl+Enter로도 제출되지 않기를 원한다.
34. 방문자로서, Ctrl 없이 Enter만 누르면 평소처럼 줄이 바뀌기를 원한다.

### 비밀번호 보기 토글

35. 방문자로서, 글 비밀번호 입력칸 옆의 눈 아이콘을 눌러 입력한 값을 보고 싶다. 그래야 오타를 확인할 수 있다.
36. 방문자로서, 다시 누르면 값이 가려지기를 원한다.
37. 글쓴이로서, 작성·수정·삭제의 비밀번호칸 모두에서 같은 토글을 쓰고 싶다.
38. 화면 낭독기를 쓰는 방문자로서, 토글 버튼이 "비밀번호 보기"/"비밀번호 숨기기"로 읽히기를 원한다.
39. 방문자로서, 토글 버튼을 눌러도 폼이 제출되지 않기를 원한다.
40. 방문자로서, 수정·삭제 패널을 닫았다 다시 열면 비밀번호가 다시 가려진 상태이기를 원한다.

## Implementation Decisions

### 관리자 강제 삭제 (ADR 0003)

- 별도 로그인, 관리자 화면, 엔드포인트를 만들지 않는다. 기존 `DELETE /api/entries/[id]`와 요청 본문 `{ password }`를 그대로 쓴다.
- 판정 순서:
  1. 400: 글 번호 → 요청 본문. 관리자 비밀번호도 기존 삭제 입력 검증(4~50자)을 거친다.
  2. 관리자 비밀번호와 비교해 맞으면 바로 삭제한다. 삭제된 행이 없으면 404, 있으면 204.
  3. 틀리면 기존 흐름으로 이어간다: 404(글 없음) → 403(글 비밀번호 불일치) → 204.
- `PATCH`는 바꾸지 않는다. 관리자 비밀번호로는 수정할 수 없다.
- 응답은 일반 삭제와 같다. 관리자인지 알려주는 필드나 헤더를 두지 않는다.
- **관리자 비밀번호 비교 함수(순수, 글 비밀번호 모듈에 추가):**
  - `(입력 비밀번호, 설정된 관리자 비밀번호 | undefined) → boolean`
  - 환경 변수를 직접 읽지 않고, 호출하는 쪽(라우트)이 `ADMIN_PASSWORD`를 넘긴다.
  - 설정값이 없거나 빈 문자열이면 항상 false다.
  - 양쪽을 SHA-256으로 해시해 같은 길이로 만든 뒤 `timingSafeEqual`로 비교한다. 길이가 달라도 예외를 던지지 않는다.
- **`ADMIN_PASSWORD` 운영 규칙:** 16~50자 무작위 값으로, 코드로 강제하지 않는다. 로컬 `.env.local`에는 추가돼 있다. Vercel 환경 변수에는 아직 없어서, 배포 전에 사람이 추가하고 다시 배포해야 한다.
- 삭제 폼의 비밀번호칸 근처에 "관리자 비밀번호도 사용할 수 있습니다."를 작은 글씨로 표시한다. 수정 폼에는 표시하지 않는다.

### 오류 화면

- 루트 세그먼트에 `error` 파일 규칙을 쓰는 클라이언트 컴포넌트를 둔다.
- 한국어 안내와 "다시 시도" 버튼을 보여준다. 버튼은 Next 16의 `retry()`를 호출해 데이터를 다시 받아 렌더링한다. 이 버전 문서는 `reset()`보다 `retry()`를 권한다.
- 이 경계는 같은 세그먼트의 루트 레이아웃은 감싸지 않는다. 그래서 헤더와 푸터는 오류가 나도 남는다. `global-error`는 만들지 않는다. 레이아웃이 DB 오류로 죽지 않게 하는 방법은 아래 "총 글 수" 참고.
- 오류 객체의 메시지나 스택은 화면에 보여주지 않는다.

### 로딩 표시

- 루트 세그먼트에 `loading` 파일 규칙을 둔다.
- 글 카드 모양의 스켈레톤 3개를 `animate-pulse`로 보여준다.
- 성공 후 `router.refresh()`로 다시 받을 때는 기존 목록이 유지되므로 스켈레톤이 뜨지 않아도 된다.

### 총 글 수

- 헤더(루트 레이아웃)에 "총 N개"를 표시한다. 개수는 글 저장소에 추가하는 개수 조회로 얻는다.
- 헤더의 개수 표시는 비동기 서버 컴포넌트로 만든다.
  - 스스로 오류를 잡아, 실패하면 개수만 숨긴다.
  - 레이아웃 전체를 막지 않도록 Suspense로 감싸고, 불러오는 동안에는 개수 자리를 비워 둔다.
- 방명록 페이지의 "전체 글 N개" 제목은 없앤다. 빈 방명록 안내는 그대로 둔다.
- 글을 남기거나 지운 뒤의 `router.refresh()`로 헤더 개수도 함께 갱신된다.
- 레이아웃은 요청마다 DB를 읽게 된다. 페이지가 이미 `force-dynamic`이므로 추가 설정이 필요한지는 구현할 때 이 버전 문서로 확인한다.

### 메시지 글자 수

- 입력 검증 모듈이 글자 수 세기 함수를 내보낸다.
  - 코드포인트 기준으로 센다(`[...s].length`). 메시지처럼 trim할지는 인자로 받는다.
  - 서버 검증도 같은 함수로 센다. 화면 숫자와 서버 판정이 어긋나지 않게 하기 위해서다.
- 작성·수정 메시지 입력칸 아래에 "현재/500"을 표시한다. 500은 검증 모듈의 길이 제한 상수에서 가져온다.
- 500자를 넘으면 숫자를 빨간색으로 바꾸고 등록·저장 버튼을 비활성화한다. 최종 판정은 서버가 한다.
- 메시지 입력칸의 `maxLength`는 없앤다. UTF-16 단위로 세기 때문에 코드포인트 기준과 어긋난다. 이름·비밀번호 입력칸의 `maxLength`는 그대로 둔다.

### Ctrl+Enter 등록

- 작성·수정 메시지 입력칸에서 Ctrl+Enter 또는 Meta(Cmd)+Enter를 누르면 폼의 `requestSubmit()`을 호출한다. 그래서 브라우저 기본 검증과 기존 제출 흐름을 그대로 탄다.
- 한글 조합 중(`isComposing`)에는 무시한다.
- 요청을 처리하는 중이거나 500자를 넘었을 때는 제출하지 않는다. 버튼이 비활성화된 상태와 같게 맞춘다.
- Enter만 누르면 기본 동작(줄바꿈)을 유지한다.
- 두 입력칸에서 같은 동작을 쓰므로 한 곳에 모은다(공용 핸들러나 공용 메시지 입력 컴포넌트).

### 비밀번호 보기 토글

- 공용 비밀번호 입력 컴포넌트를 만들어 작성·수정·삭제의 비밀번호칸을 모두 교체한다.
- 입력칸 옆에 인라인 SVG 눈 아이콘 버튼을 둔다. 아이콘 라이브러리는 추가하지 않는다.
- 버튼은 `type="button"`이고, `aria-label`은 상태에 따라 "비밀번호 보기"/"비밀번호 숨기기"다.
- 보기 상태는 컴포넌트 안에만 둔다. 수정·삭제 패널을 닫으면 컴포넌트가 사라지므로 다시 열면 가려진 상태로 돌아온다.
- 기존 입력 속성(`minLength`, `maxLength`, `required`, `autoComplete`)은 그대로 넘긴다.

### 바뀌지 않는 것

- DB 스키마, 기존 API 계약(요청·응답 모양, 상태 코드, 안내 문구)은 그대로다. 달라지는 것은 `DELETE`의 강제 삭제 분기 하나뿐이다.
- 로컬과 배포가 같은 DB를 쓰는 구조(ADR 0002)와 비밀번호 해시 형식(ADR 0001)도 그대로다.

## Testing Decisions

- **도구:** 기존 Vitest. 자동 테스트는 DB와 브라우저에 닿지 않는 순수 로직만 다룬다.
- **좋은 테스트의 기준:** 공개 함수에 입력을 넣고 결과만 확인한다. 기대값은 스펙의 리터럴이나 손으로 계산한 예시에서 가져온다. 상수 값 자체를 확인하는 테스트는 쓰지 않는다.
- **Seam (사용자 확인 완료, 둘 다 기존 모듈):**
  1. **입력 검증 모듈의 글자 수 세기 함수**
     - 이모지를 1글자로 세는지
     - trim 옵션에 따라 앞뒤 공백을 빼는지
     - 한글, 줄바꿈이 섞인 문자열
     - 500자 경계에서 기존 메시지 검증과 같은 판정인지
  2. **글 비밀번호 모듈의 관리자 비밀번호 비교 함수**
     - 맞으면 true, 틀리면 false
     - 길이가 달라도 예외 없이 false
     - 설정값이 undefined이거나 빈 문자열이면, 빈 입력을 포함한 어떤 입력이든 false
     - 앞뒤 공백 한 글자만 달라도 false(관리자 비밀번호도 trim하지 않음)
- **자동 테스트하지 않는 것:** `DELETE`의 강제 삭제 분기, 오류·로딩 화면, 헤더의 총 글 수, 글자 수 표시 화면, Ctrl+Enter, 비밀번호 보기 토글. 개발 서버에서 수동으로 확인한다.
  - 강제 삭제는 테스트 글을 만든 뒤 관리자 비밀번호로 지운다. 확인과 정리를 한 번에 하기 위해서다(공유 DB, ADR 0002).
  - 강제 삭제 수동 확인 항목:
    - 관리자 비밀번호로 204
    - 없는 글에 관리자 비밀번호로 404
    - 틀린 값이면 기존 403
    - 관리자 비밀번호로 `PATCH`하면 403
  - 오류 화면은 DB를 망가뜨리지 않고 확인한다. 로컬에서 잠시 `DATABASE_URL`을 틀린 값으로 바꿔 띄우는 식이고, 확인 후 되돌린다.
  - 한글 입력은 UTF-8 본문으로 보낸다(Windows curl은 CP949로 보냄).
- **기존 테스트:** `lib/*.test.ts`의 입력 검증, 글 비밀번호, KST 표시 테스트가 같은 방식(`describe`/`it.each`, 한국어 테스트 이름)이다. 기존 49개는 그대로 통과해야 한다.

## Out of Scope

- 관리자 로그인·세션·관리자 전용 화면, 관리자에 의한 수정
- 관리자 비밀번호 변경 화면, 관리자 여러 명
- 강제 삭제 기록(누가 언제 지웠는지), 삭제 되돌리기
- 관리자 비밀번호 무차별 대입 방지(rate limit, 잠금). 긴 무작위 값으로 대신한다.
- `global-error` 화면
- 이름 입력칸의 글자 수 표시
- 기존 스펙의 Out of Scope 중 이 스펙이 바꾸지 않은 항목(페이지네이션, 다크 모드, DB 분리 등)
