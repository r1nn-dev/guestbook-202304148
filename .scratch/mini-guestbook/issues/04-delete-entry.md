# 04: 글 삭제하기

**What to build:** 글쓴이가 자기 글 안에서 "삭제"를 누르면 글 비밀번호 입력칸이 그 글 안에 펼쳐진다. 비밀번호가 맞으면 별도의 확인 창 없이 글이 방명록에서 사라진다. 비밀번호가 틀리면 그 글 안에 "비밀번호가 일치하지 않습니다."가 보인다. 이미 지워진 글이면 "글을 찾을 수 없습니다."가 보인다.

**Blocked by:** 03 (메시지 수정하기). 03이 만든 글 항목 패널과 글 번호 라우트를 이어서 쓴다.

**Status:** ready-for-agent

- [x] 입력 검증 모듈의 삭제 입력은 비밀번호(4~50자, 원본)만 본다. 객체가 아닌 본문은 "잘못된 요청입니다."를 돌려준다.
- [x] 삭제 입력 테스트: 맞는 비밀번호, 너무 짧은 비밀번호, 본문 없음.
- [x] 글 저장소는 글 번호로 글을 삭제하고, 삭제된 행이 없으면 "없음"을 돌려준다.
- [x] `DELETE /api/entries/[id]`는 JSON 본문 `{ password }`를 받는다. 판정 순서:
  - 400: 글 번호 → 본문
  - 404
  - 403
  - 성공: 204, 본문 없음
  - 비밀번호 확인과 삭제 사이에 글이 지워졌으면 404다.
- [x] 글 항목에 삭제 상태를 추가한다.
  - "삭제"를 누르면 비밀번호칸이 열리고, "취소"를 누르면 닫힌다.
  - 요청을 처리하는 동안 버튼을 비활성화한다.
  - 성공하면 `router.refresh()`를 호출한다.
  - 오류 안내는 그 글 안에만 보인다.
- [x] 수정 흐름(03)이 그대로 동작한다.
- [x] 수동 확인: 개발 서버에서 400, 404, 403, 204를 확인한다. 끝나면 공유 DB에 테스트 글이 남아 있지 않다.
- [x] `npm test`, 타입 검사, 린트, `npm run build`가 모두 통과한다.

## Comments

- 구현 완료. TDD로 삭제 입력 테스트 3개를 추가했다(전체 48개 통과).
- 개발 서버에서 작성 → 수정 → 삭제를 한 번에 수동 확인했다. 결과:
  - `POST` 201, 앞뒤 공백 제거, 줄바꿈과 이모지 유지, 해시 노출 없음
  - `PATCH` 틀린 비밀번호 403, 성공 200(`updatedAt` 기록, 작성자 이름 변경 무시), 페이지에 "(수정됨)"
  - `DELETE` 틀린 비밀번호 403, 짧은 비밀번호 400, 잘못된 글 번호 400, 성공 204, 다시 삭제하면 404
- 확인 뒤 `GET`은 `[]`이고, 공유 DB에 테스트 글이 남아 있지 않다. 테스트 글은 id 2를 썼다.
