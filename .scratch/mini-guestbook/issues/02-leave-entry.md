# 02: 글 남기기

**What to build:** 방문자가 작성자 이름, 메시지, 글 비밀번호를 입력해 글을 남기면 입력칸이 비워지고, 새 글이 방명록 맨 위에 바로 보인다. 입력이 규칙에 맞지 않으면 폼 아래에 무엇이 잘못됐는지 안내 문구 하나가 보인다. 글 비밀번호는 원문이 아니라 scrypt `salt:hash`로 저장된다(ADR 0001).

**Blocked by:** 01 (방명록 보기 + 개발자 정보)

**Status:** ready-for-agent

- [x] 입력 검증 모듈(순수)의 작성 입력 검사:
  - 이름·메시지는 trim한 뒤 검사하고, 비밀번호는 원본 그대로 검사한다.
  - 길이는 코드포인트 기준으로 이름 1~20자, 메시지 1~500자, 비밀번호 4~50자다.
  - 문자열이 아닌 값과 객체가 아닌 본문(null, 배열, 문자열)은 거부한다.
  - 여러 필드가 틀리면 이름 → 메시지 → 비밀번호 순서로 첫 오류 하나만 돌려준다.
  - 결과는 `{ ok: true, value }` 또는 `{ ok: false, error }`다.
- [x] 안내 문구와 길이 제한 상수는 입력 검증 모듈이 소유한다. 문구는 다음과 같다.
  - "잘못된 요청입니다."
  - "이름은 1~20자로 입력해주세요."
  - "메시지는 1~500자로 입력해주세요."
  - "비밀번호는 4~50자로 입력해주세요."
- [x] 입력 검증 테스트:
  - trim과 비밀번호 무변형
  - 공백뿐인 값
  - 20/21자, 500/501자, 3/4/50/51자 경계
  - 이모지를 한 글자로 세는지
  - 문자열이 아닌 값, 객체가 아닌 본문
  - 첫 오류 하나만 돌려주는지
- [x] 글 비밀번호 모듈(순수):
  - `hash`는 16바이트 salt와 64바이트 키로 hex `salt:hash`를 만든다.
  - `verify`는 `timingSafeEqual`로 비교한다.
  - 형식이 깨진 저장값은 예외 없이 false를 돌려준다.
- [x] 글 비밀번호 테스트:
  - 형식
  - 같은 비밀번호라도 매번 다른 결과
  - 원문을 포함하지 않음
  - 맞는 비밀번호는 통과, 틀린 비밀번호와 공백 차이는 거부
  - 깨진 저장값(빈 문자열, 콜론 없음, 빈 조각, 키 길이 불일치)은 false
- [x] `POST /api/entries`:
  - 성공하면 201과 생성된 글(해시 없음)을 돌려준다.
  - 검증에 실패하면 400과 `{ error }`를 돌려준다.
  - JSON이 아닌 본문도 400이다.
- [x] 작성 폼(클라이언트 컴포넌트):
  - 요청을 처리하는 동안 버튼을 비활성화한다.
  - 성공하면 입력칸을 비우고 `router.refresh()`로 목록을 갱신한다.
  - 실패하면 서버가 보낸 안내를 폼 안에 보여준다.
  - 네트워크가 실패하면 "서버에 연결하지 못했습니다."를 보여준다.
  - 입력칸의 제한값은 검증 모듈의 상수를 쓴다.
- [ ] 수동 확인: 개발 서버에서 201과 400을 확인하고, 만든 테스트 글은 지운다(공유 DB, ADR 0002).
  - 한글 입력은 UTF-8 본문으로 보낸다. Windows curl은 한글 인자를 CP949로 보내 글자가 깨진다.
- [x] `npm test`, 타입 검사, 린트, `npm run build`가 모두 통과한다.
