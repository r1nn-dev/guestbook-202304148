# 03: 메시지 수정하기

**What to build:** 글쓴이가 자기 글 안에서 "수정"을 누르면 현재 메시지가 채워진 편집칸과 글 비밀번호 입력칸이 그 글 안에 펼쳐진다. 비밀번호가 맞으면 메시지가 바뀌고, 편집칸이 닫히며 "(수정됨)"이 붙는다. 글의 순서는 그대로다. 비밀번호가 틀리면 그 글 안에 "비밀번호가 일치하지 않습니다."가 보이고, 편집칸과 입력한 메시지는 남아 있다. 작성자 이름은 고칠 수 없다.

**Blocked by:** 02 (글 남기기)

**Status:** ready-for-agent

- [x] 입력 검증 모듈에 추가:
  - 수정 입력은 메시지(trim, 1~500자)와 비밀번호(4~50자, 원본)만 본다. 이름이 들어와도 무시한다.
  - 메시지 오류가 비밀번호 오류보다 먼저다.
  - 글 번호는 앞자리가 0이 아닌 1~18자리 양의 정수 문자열만 허용하고, 그 밖에는 "잘못된 글 번호입니다."를 돌려준다.
- [x] 입력 검증 테스트:
  - 수정 입력에서 이름을 무시하는지, 메시지 오류가 먼저인지
  - 글 번호 허용: 1, 42, 18자리
  - 글 번호 거부: 0, -1, 01, 1.5, abc, 빈 문자열, 19자리
- [x] 글 저장소:
  - 글 번호로 비밀번호 해시를 조회한다. 없으면 "없음"을 돌려준다.
  - 메시지를 수정하면서 `updated_at = now()`로 기록하고, 대상 행이 없으면 "없음"을 돌려준다.
  - 조회에 `select *`는 쓰지 않는다.
- [x] `PATCH /api/entries/[id]` 판정 순서:
  - 400: 글 번호 → 본문(JSON이 아닌 본문 포함)
  - 404: "글을 찾을 수 없습니다."
  - 403: "비밀번호가 일치하지 않습니다."
  - 성공: 200과 수정된 글(해시 없음)
  - 비밀번호 확인과 수정 사이에 글이 지워졌으면 404다.
- [x] 라우트 핸들러의 `params`는 Promise로 다룬다(Next 16 문서를 확인할 것).
- [x] 글 항목(클라이언트 컴포넌트)에 보기/수정 상태를 둔다.
  - "수정"을 누르면 편집칸과 비밀번호칸이 열리고, "취소"를 누르면 원래 메시지로 돌아간다.
  - 요청을 처리하는 동안 버튼을 비활성화한다.
  - 성공하면 `router.refresh()`를 호출한다.
  - 오류 안내는 그 글 안에만 보이고, 다른 글의 패널과 섞이지 않는다.
- [x] 같은 메시지로 저장해도 거부하지 않고, 이 경우에도 "(수정됨)"이 붙는다.
- [x] 수동 확인: 개발 서버에서 400(잘못된 글 번호, 빈 메시지), 404, 403, 200을 확인하고, 만든 테스트 글은 지운다(공유 DB).
- [x] `npm test`, 타입 검사, 린트, `npm run build`가 모두 통과한다.
